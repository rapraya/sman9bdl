## 7. AI SCHOOL INFORMATION CHATBOT — TANPA API KEY

Website wajib memiliki chatbot informasi sekolah yang dapat digunakan pengunjung tanpa memerlukan API Key dari OpenAI, Gemini, Claude, atau layanan AI berbayar lainnya.

### Prinsip utama

Bangun chatbot berbasis database sekolah menggunakan pendekatan:

**Database-Powered Information Retrieval / Rule-Based Conversational Assistant.**

Chatbot harus mampu memberikan jawaban berdasarkan informasi yang tersedia di database website.

Tidak boleh berpura-pura menggunakan AI generatif jika sebenarnya hanya menggunakan pencocokan kata atau FAQ.

### Sumber pengetahuan chatbot

Chatbot harus dapat mengambil informasi dari:

- Profil sekolah.
- Visi dan misi.
- Sejarah sekolah.
- Berita.
- Pengumuman.
- Agenda.
- Prestasi.
- Fasilitas.
- Program sekolah.
- Kontak.
- Halaman informasi.
- Dokumen publik yang telah diindeks.

### Kemampuan chatbot

1. Memahami pertanyaan umum menggunakan normalisasi teks.
2. Mencocokkan kata kunci dan sinonim.
3. Menggunakan pencarian full-text database.
4. Menggunakan pencarian semantik lokal apabila tersedia.
5. Menampilkan jawaban yang relevan.
6. Menampilkan sumber informasi atau tautan halaman.
7. Memberikan rekomendasi pertanyaan lanjutan.
8. Menangani pertanyaan yang tidak ditemukan.
9. Mendukung percakapan berkelanjutan dengan konteks sesi secara terbatas.
10. Menyediakan tombol membuka halaman sumber informasi.

### Contoh pertanyaan

- Di mana alamat sekolah?
- Siapa kepala sekolah saat ini?
- Apa visi dan misi sekolah?
- Apa saja fasilitas sekolah?
- Bagaimana cara menghubungi sekolah?
- Apa berita terbaru?
- Apa saja prestasi sekolah?
- Kapan kegiatan sekolah berikutnya?
- Di mana informasi SPMB dapat ditemukan?

### Aturan akurasi chatbot

- Jawaban hanya berdasarkan data yang tersedia.
- Jangan mengarang informasi.
- Jangan membuat tanggal atau nama pejabat sendiri.
- Jangan memberikan jawaban yang tidak memiliki sumber.
- Jika informasi tidak ditemukan, sampaikan dengan sopan bahwa informasi belum tersedia.
- Berikan tautan menuju sumber informasi yang relevan.
- Prioritaskan informasi terbaru yang telah dipublikasikan.
- Informasi privat dan data administrator tidak boleh diakses chatbot publik.

### Arsitektur tanpa API Key

Gunakan teknologi lokal:

- PHP untuk pemrosesan permintaan.
- MySQL/MariaDB untuk basis pengetahuan.
- Full-text search untuk pencarian informasi.
- Algoritma pencocokan kata dan relevansi.
- Session untuk konteks percakapan terbatas.
- Fetch API untuk komunikasi chatbot.

Jika ingin kemampuan bahasa yang lebih natural, AI boleh mempertimbangkan model bahasa lokal melalui Ollama atau solusi lokal sejenis, tetapi hanya jika infrastruktur server mendukungnya.

Jangan menjadikan model lokal sebagai syarat agar chatbot dasar berfungsi.

**Target:** Chatbot tetap dapat bekerja tanpa API Key, tanpa biaya token, dan tanpa ketergantungan pada layanan AI eksternal.

## 14. ATURAN KHUSUS PENAMAAN FILE DAN KODE — WAJIB

AI DILARANG menggunakan penanda versi dalam penamaan file, script, CSS, JavaScript, maupun komentar kode.

### Contoh yang dilarang

- `style-v2.css`
- `main-v3.js`
- `header-new.php`
- `homepage-final.php`
- `custom-latest.css`
- `script-fix-2028.js`
- `website-version-2.php`
- `style-final-revisi.css`

Juga dilarang membuat nama seperti:

- `header_backup_new.php`
- `main_updated.js`
- `style_perbaikan_terbaru.css`
- `homepage_alternatif.php`

### Aturan yang wajib dipatuhi

1. Gunakan satu nama file utama yang konsisten.
2. Jika file CSS sudah ada, perbaiki file tersebut.
3. Jika JavaScript sudah ada, kembangkan script yang sama sesuai arsitektur.
4. Jangan membuat duplikasi file hanya karena melakukan revisi.
5. Jangan membuat file alternatif untuk menggantikan file utama tanpa alasan teknis.
6. Jangan menggunakan penanda versi atau revisi pada nama file, nama class, nama fungsi, maupun komentar kode.
7. Jangan menambahkan komentar seperti `// Version 2`, `/* Updated Version */`, atau `/* New Design 2028 */`.
8. Gunakan komentar hanya untuk menjelaskan fungsi, logika, atau bagian kode yang memang memerlukan penjelasan.
9. Pertahankan satu sumber utama (Single Source of Truth) untuk setiap komponen.
10. Pastikan seluruh referensi file, asset, route, dan dependency tetap sinkron.

Nama file harus menggambarkan fungsi sebenarnya, misalnya:

- `header.php`
- `footer.php`
- `home.php`
- `style.css`
- `main.js`
- `accessibility.js`
- `chatbot.js`
- `accessibility.css`
- `chatbot.css`

Pengecualian: penetapan versi dependency yang memang diperlukan oleh Composer, package manager, atau lockfile tetap diperbolehkan untuk menjaga kompatibilitas. Larangan ini berlaku pada penamaan dan komentar, bukan pada metadata teknis dependency.

## 19. TARGET AKHIR WEBSITE

Website yang dihasilkan wajib memiliki karakter:

**INFORMATIVE — PROFESSIONAL — PREMIUM — MODERN — ACCESSIBLE — INTELLIGENT — FUTURE-READY.**

Website harus terasa seperti portal resmi institusi pendidikan modern, bukan website sekolah konvensional yang hanya mengganti warna dan template.

Prioritas utama:

1. Identitas dan kredibilitas sekolah.
2. Informasi yang akurat dan mudah ditemukan.
3. Desain premium dan konsisten.
4. Kemudahan penggunaan.
5. Aksesibilitas untuk semua pengunjung.
6. Chatbot informasi sekolah yang akurat.
7. Keamanan dan perlindungan data.
8. Performa dan SEO.
9. Kemudahan pengelolaan melalui CMS.
10. Kemudahan pengembangan jangka panjang.

### INSTRUKSI PENUTUP

Sebelum menulis kode, lakukan analisis kebutuhan dan buat rancangan struktur website secara menyeluruh.

Tunjukkan rancangan sitemap, struktur navigasi, konsep desain beranda, struktur database, dan arsitektur aplikasi terlebih dahulu.

Jangan langsung menghasilkan website dengan desain generik.

Pastikan setiap keputusan desain dan teknis memiliki alasan yang jelas.

**Saya menginginkan website SMA Negeri dengan kualitas visual dan pengalaman pengguna yang mencerminkan perkembangan teknologi serta desain digital 2027–2040, tetapi tetap profesional, berwibawa, informatif, mudah diakses, dan relevan untuk institusi pendidikan negeri.**

Hasil akhir bukan hanya website yang indah dilihat, tetapi sebuah ekosistem informasi pendidikan digital yang benar-benar berfungsi, dapat dikelola, aman, dan berkelanjutan.
